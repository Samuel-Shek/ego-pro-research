# Ego Lite 与 Pro 的操作

先读取实际安装的官方 `ego-browser` Skill。以下仅描述 ChatGPT 工作流，不替代当前上游接口文档。优先后台操作；本包不移动系统窗口。

## 空间与页面

```bash
ego-browser nodejs <<'JS'
const task = await taskSpace("Pro research");
console.log({ spaceId: task.spaceId, ownership: task.ownership });
const page = task.page("p1");
await page.goto("https://chatgpt.com/");
console.log(await page.snapshot());
JS
```

记录实际 `spaceId` 和页面标签；后续恢复同一空间，不假设脚本变量跨轮存在。导航超时但 URL 已提交时，先观察原页面，不新建空间或重发。上游与宿主授权约束优先，不能换空间绕过用户接管或不确定送达。

浏览器脚本的工作目录可能与宿主命令所在目录不同。读取冻结提示词、上传附件和保存证据一律使用已核对的绝对路径，不依赖相对路径或默认目录。需要按当前页面标识执行底层操作时，新取得的 Page 句柄先完成 `await page.info()` 等观察，再核对非空的 `page.targetId`；不要跨脚本缓存该标识。

发送前核对 https、chatgpt.com、当前阶段、登录账号与控制权。首次研究须是没有旧消息和 GPT/插件绑定的新普通聊天；恢复或补充默认使用当前绑定研究会话；必要迁移须满足下文条件，新旧会话均核对阶段和状态。禁止把 `/share/` 当研究入口。需要新普通聊天时使用当前页面可观察控件，不靠 URL 形式猜测页面为空。

## 当前最高 Pro

观察模型按钮，打开菜单后重新观察候选。只选择实际可选模型/推理档位，排除升级、订阅和付款入口。若模型与推理强度分开显示，两者都要核对。优先最高 Pro（如 Pro Extended），没有更高选项时才能用 Pro Standard；Thinking、High、Extra High 或 Instant 不是 Pro 的静默替代。点击后重新确认选中状态。

## 一次发送与等待

从快照定位编辑器、填写、读回，与冻结终稿核对；附件名、数量及完成状态也需检查。点击可观察的发送按钮，确认内容出现为真实用户消息，保存实际会话 URL，不推导地址。消息结果不明时只查原会话；不能用点击回执证明送达。

网页结构会变化。只使用当前快照确认的编辑器和对话区域，不预设旧输入框 ID、消息属性或首个 `main` 就是聊天。快照引用在页面变化后须重新取得；子树观察的根也必须是当前快照引用。附件上传成功还不足以证明内容读取正确，验收时核对实际条目、数值及重要末尾内容。

富文本编辑器的显示文本可能增加空行或在链接处换行；先检查实际段落内容是否保留原文，不因显示差异盲目重填。代码、命令和精确字符串仍须逐项保真，不能以宽泛清理空白掩盖内容差异。

生成期间只等待、观察及简短播报，不催促、停止或重复发送。单次阻塞等待不超过 60 秒以便及时响应，不是生成或任务总时限；按状态安排观察间隔，不忙轮询。完整回复仍需宿主核验。补充和纠错默认留在当前绑定聊天；可为未解决问题、明确复核目的或新输入继续，不机械重复。首次协作和纯补证不计纠错，以修正既有候选为目的的往返（包括新证据触发的修正）计一轮，Pro 纠错按实际需求进行，不设固定轮数；仍有明确问题需要解决时继续，达到验收要求后交付。每轮核对实际进展；相同尝试没有进展时调整问题、补充证据或改用宿主独立验证，不机械重复，也不因次数自动放弃任务。保留原会话及尝试历史，轮数仅作过程记录。宿主可继续原授权内独立核验和处理，未解决缺陷不报完成。

## 按状态恢复与续接

有页面失活、断连或加载失败的可观察依据时，可在权限与控制权仍允许时只读重开保存的原 URL，不设固定恢复次数；正文暂时不变不能单独证明失活，正常生成不打断。每次检查会话、送达与生成状态及失败原因，新状态或可靠恢复依据支持继续；相同动作无进展则调整诊断、等待恢复条件或暂停依赖部分，不循环重开，不重发已送达或送达不明的任务。

当前可观察且语义明确的无害信息提示、已授权回复的继续生成，可按需处理并逐次核对实际结果；结果不明先核查，不把旧按钮仍可见当成重点击依据，继续生成不得重做旧提交。相同提示反复无变化先诊断。账号、付款、权限、共享、连接器及含义不清的确认仍交给用户，不能借提示处理扩权。

优化与研究分别默认复用原会话。原会话无法继续，或上下文长度、混杂已实质妨碍任务时，先核查原因、送达及生成状态；仅确认无送达不明或仍在生成的请求，且原授权、退出与控制权均允许，才可迁移。状态未明时暂停迁移并查原会话，不借新聊天重复发送或绕过接管。

保留原 URL、迁移原因、有效约束、已验证结论、待解决问题及尝试历史，以最小脱敏摘要与必要附件交接。新研究会话仍为普通聊天并重新确认最高 Pro；可选网页优化仍用用户已指定入口。记录新旧恢复键，任务退出与历史不清零。首次或迁移需自足背景，同一上下文完整的会话可只发送明确增量和仍有效要求。这些条件适用于其他参考中的原会话续接规则。

## 控制权与结束

登录、验证码、账号选择、支付和权限要求用上游 `handOff()` 交给用户，等待真实答复后按上游接口恢复。用户控制期间不重试或继续观察。没有副屏不影响后台路径；没有浏览器控制权或登录则暂停相关步骤。

仅当任务结果已被宿主消费并完成验收时，单独执行 `await task.finish({ keep: [] })` 并等待返回；必要结果页面仅在用户要求或确需继续查看时保留。结束任务空间不删除账号中的 ChatGPT 历史。
