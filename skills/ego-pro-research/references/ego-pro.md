# Ego Lite 与 Pro 的操作

先读取实际安装的官方 `ego-browser` Skill。以下仅描述 ChatGPT 工作流，不替代当前上游接口文档。优先后台操作；本包不移动系统窗口。

## 空间与页面

```bash
ego-browser nodejs <<'JS'
const task = await taskSpace("Pro research");
console.log({ spaceId: task.spaceId, ownership: task.ownership });
const page = task.page("p1");
await page.goto("https://chatgpt.com/");
console.log(await page.snapshot());
JS
```

记录实际 `spaceId` 和页面标签；后续恢复同一空间，不假设脚本变量跨轮存在。导航超时但 URL 已提交时，先观察原页面，不新建空间或重发。上游与宿主授权约束优先，不能换空间绕过用户接管或不确定送达。

发送前核对 https、chatgpt.com、当前阶段、登录账号与控制权。首次研究须是没有旧消息和 GPT/插件绑定的新普通聊天；恢复或补充须是已绑定的原研究会话。禁止把 `/share/` 当研究入口。需要新普通聊天时使用当前页面可观察控件，不靠 URL 形式猜测页面为空。

## 当前最高 Pro

观察模型按钮，打开菜单后重新观察候选。只选择实际可选模型/推理档位，排除升级、订阅和付款入口。若模型与推理强度分开显示，两者都要核对。优先最高 Pro（如 Pro Extended），没有更高选项时才能用 Pro Standard；Thinking、High、Extra High 或 Instant 不是 Pro 的静默替代。点击后重新确认选中状态。

## 一次发送与等待

从快照定位编辑器、填写、读回，与冻结终稿核对；附件名、数量及完成状态也需检查。点击可观察的发送按钮，确认内容出现为真实用户消息，保存实际会话 URL，不推导地址。消息结果不明时只查原会话；不能用点击回执证明送达。

富文本编辑器的显示文本可能增加空行或在链接处换行；先检查实际段落内容是否保留原文，不因显示差异盲目重填。代码、命令和精确字符串仍须逐项保真，不能以宽泛清理空白掩盖内容差异。

生成期间只等待、观察及简短播报，不催促、停止或重复发送。单次等待不超过 60 秒。完整回复仍需宿主核验。纠错留在原聊天；无新输入不重复征询。

## 控制权与结束

登录、验证码、账号选择、支付和权限要求用上游 `handOff()` 交给用户，等待真实答复后按上游接口恢复。用户控制期间不重试或继续观察。没有副屏不影响后台路径；没有浏览器控制权或登录则暂停相关步骤。

仅当任务结果已被宿主消费并完成验收时，单独执行 `await task.finish({ keep: [] })` 并等待返回；必要结果页面仅在用户要求或确需继续查看时保留。结束任务空间不删除账号中的 ChatGPT 历史。
